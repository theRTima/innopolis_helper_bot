# innopolis_helper_bot

Корпоративный Telegram-бот с поиском по документации. Ветка `rag-pipeline`:
реализация по отдельным проверяемым чекпоинтам.

## Чекпоинт 1: загрузка PDF

Требуется Python 3.11+. Команды PowerShell из корня репозитория:

```powershell
cd D:\HackInno\innopolis_helper_bot
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m rag_pipeline.ingest "D:\path\Командировка.pdf" --document-id travel
```

Замените путь к PDF на свой. Активация окружения не нужна.
CLI печатает JSON в stdout, ошибки — в stderr с кодом завершения 1.
Для корректного файла возвращает код 0, `duplicate: false` и `version_path`.
Запустите последнюю команду повторно: будет `duplicate: true` с прежней версией.

Результат относительно текущей рабочей папки:

```text
data/processed/documents/
  travel/
    sha256-<полный SHA-256>/
      original.pdf
      manifest.json
```

В manifest: версия схемы, ID документа и версии, исходное имя, SHA-256,
размер, число страниц, UTC-время загрузки, статус `uploaded` и путь к оригиналу.
Это файловый реестр метаданных; PostgreSQL на первом этапе не требуется.

`--document-id` — постоянный ID логического документа. Используйте `travel`
и для следующей редакции инструкции: изменённое содержимое создаст новую версию,
старая останется. Одинаковые байты под другим именем в рамках того же ID — дубликат.
Под другим ID файл считается отдельным документом. ID: 1–80 строчных латинских
букв, цифр, дефисов или подчёркиваний, первый символ — буква или цифра;
зарезервированные имена Windows запрещены.

Папку хранения можно задать явно:

```powershell
.\.venv\Scripts\python.exe -m rag_pipeline.ingest "D:\path\Командировка.pdf" --document-id travel --storage-root "D:\HackInno\pdf-storage"
```

Исходник сначала копируется во временный каталог, затем эта копия проверяется
через pypdf в строгом режиме: заголовок, дерево страниц и декодирование содержимого
страниц. Парольные, пустые и нечитаемые PDF отклоняются. Это проверка читаемости,
а не доказательство корректности рендеринга, OCR или полноты будущего извлечения.
Готовая папка версии появляется только после успешной проверки. При дубликате
проверяется целостность уже сохранённого оригинала и ключевые поля manifest.

Одновременная запись одного документа блокируется `.ingest.lock`. После аварийного
завершения lock и `.staging-*` могут остаться: удалять их вручную можно только
убедившись, что процесс загрузки уже не работает. Сохранённые версии не редактируйте.
Перемещение каталога защищает от публикации частичного результата при обычной ошибке;
гарантия сохранности при отключении питания пока не реализована.

`data/processed/` уже исключена из Git: внутренние PDF и runtime-manifest не попадают
в коммиты. Не направляйте хранилище в отслеживаемую папку без настройки `.gitignore`.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверяются сохранение и хеш, число страниц, повторная загрузка, новая редакция,
повреждённый/зашифрованный/пустой PDF, небезопасный ID, отсутствующий файл,
повреждение сохранённого оригинала и блокировка параллельной записи.
Тесты используют синтетические PDF и не требуют внутренних документов.

Следующий чекпоинт после пользовательской проверки: рендеринг всех страниц.
OCR, Docling/OpenParse, чанки, векторный поиск и генерация ответов пока не подключены.
