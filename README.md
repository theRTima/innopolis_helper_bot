# innopolis_helper_bot

Корпоративный Telegram-бот с поиском по документации. Ветка `rag-pipeline`:
реализация по отдельным проверяемым чекпоинтам.

## Чекпоинт 1: загрузка файлов

Все форматы используют общее хранение версий и SHA-256. Различается только проверка
читаемости. Таблица ниже описывает поддержку загрузки, а не готовое извлечение для RAG.

| Источник | Проверка при загрузке |
| --- | --- |
| PDF | Заголовок, страницы, декодирование потоков |
| DOCX | ZIP/CRC, XML, открытие python-docx; число верхнеуровневых абзацев, таблиц и секций |
| XLSX | ZIP/CRC, XML, открытие openpyxl; имена и число листов |
| PPTX | ZIP/CRC, XML, открытие python-pptx; число слайдов |
| PNG, JPEG, WebP, TIFF, BMP | Формат, структура и декодирование кадров через Pillow |
| TXT, Markdown, RST, AsciiDoc, HTML, TeX | Строгое декодирование текста |
| JSON, JSONL, XML, TOML | Декодирование и проверка синтаксиса |
| YAML, INI, конфиги | Декодирование; синтаксис специфичного формата пока не проверяется |
| CSV, TSV | Декодирование и чтение записей; CSV по умолчанию с запятой |
| Код: Python, JS/TS, Java, C/C++, C#, Go, Rust, SQL и другие | Читаемость текста; код не запускается и не компилируется |
| Dockerfile, Makefile, README, LICENSE, .gitignore и другие известные имена | Читаемость текста |

Полные списки расширений и адаптеры — `rag_pipeline/formats.py`.
Для неизвестного текстового расширения есть `--format text`. Неизвестные бинарные
форматы, старые DOC/XLS/PPT, архивы и Office с макросами не принимаются.
Для них нужен отдельный конвертер/адаптер; переименование расширения не поможет.
Структурные проверки Office не подтверждают правильность отображения каждого объекта.
Формулы Excel не вычисляются, HTML/JavaScript не открываются в браузере.

Требуется Python 3.11+. Команды PowerShell из корня репозитория:

```powershell
cd D:\HackInno\innopolis_helper_bot
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m rag_pipeline.ingest "D:\path\Командировка.pdf" --document-id travel
```

Замените путь к PDF на свой. Активация окружения не нужна.
Если окружение уже создано, повторите только `pip install -e .`, чтобы установить
добавленные зависимости.
CLI печатает JSON в stdout, ошибки — в stderr с кодом завершения 1.
Для корректного файла возвращает код 0, `duplicate: false` и `version_path`.
Запустите последнюю команду повторно: будет `duplicate: true` с прежней версией.

Примеры других источников (пути замените на существующие):

```powershell
.\.venv\Scripts\python.exe -m rag_pipeline.ingest "D:\docs\Инструкция.docx" --document-id instructions
.\.venv\Scripts\python.exe -m rag_pipeline.ingest "D:\docs\API.md" --document-id api-docs
.\.venv\Scripts\python.exe -m rag_pipeline.ingest "D:\repo\service.py" --document-id service-code
.\.venv\Scripts\python.exe -m rag_pipeline.ingest "D:\docs\Схема.png" --document-id process-diagram
.\.venv\Scripts\python.exe -m rag_pipeline.ingest "D:\docs\legacy.txt" --document-id legacy --encoding cp1251
.\.venv\Scripts\python.exe -m rag_pipeline.ingest "D:\docs\notes.custom" --document-id notes --format text
```

Текст по умолчанию — UTF-8; UTF-16/32 определяются по BOM. Автоматического угадывания
CP1251 нет. Исходные байты не перекодируются. Некорректная кодировка, пустой текст
и бинарные управляющие символы приводят к отказу. Это загрузка отдельных файлов:
обход репозитория, Git-ссылки и сохранение путей кода относительно репозитория —
отдельный будущий этап.

Результат относительно текущей рабочей папки:

```text
data/processed/documents/
  travel/
    sha256-<полный SHA-256>/
      original.pdf
      manifest.json
```

В manifest: версия схемы, ID документа и версии, исходное имя, SHA-256,
размер, число страниц, UTC-время загрузки, статус `uploaded` и путь к оригиналу.
Новые manifest имеют `schema_version: 2`, поля `format`, `source_kind`, `validation`.
Для DOCX, XLSX, PPTX, текста и изображений `page_count: null`: фиксированных страниц
пока нет. Число слайдов, листов, строк или размеры изображения — в `validation`.
`original_path` указывает реальное имя: `original.docx`, `original.md` и т. д.;
у известных имён без расширения используется `original.txt`.
Прежние PDF и manifest версии 1 распознаются без миграции и перезаписи.
Это файловый реестр метаданных; PostgreSQL на первом этапе не требуется.

`--document-id` — постоянный ID логического документа. Используйте `travel`
и для следующей редакции инструкции: изменённое содержимое создаст новую версию,
старая останется. Одинаковые байты под другим именем в рамках того же ID — дубликат.
Под другим ID файл считается отдельным документом. ID: 1–80 строчных латинских
букв, цифр, дефисов или подчёркиваний, первый символ — буква или цифра;
зарезервированные имена Windows запрещены.

Папку хранения можно задать явно:

```powershell
.\.venv\Scripts\python.exe -m rag_pipeline.ingest "D:\path\Командировка.pdf" --document-id travel --storage-root "D:\HackInno\pdf-storage"
```

Исходник сначала копируется во временный каталог, затем эта копия проверяется
через pypdf в строгом режиме: заголовок, дерево страниц и декодирование содержимого
страниц. Парольные, пустые и нечитаемые PDF отклоняются. Это проверка читаемости,
а не доказательство корректности рендеринга, OCR или полноты будущего извлечения.
Готовая папка версии появляется только после успешной проверки. При дубликате
проверяется целостность уже сохранённого оригинала и ключевые поля manifest.
Лимит исходника — 50 MiB; распакованного Office-пакета — 200 MiB / 10000 записей.
XML с DTD/объявлениями сущностей не принимается. Лимиты изображений включают
стандартную защиту Pillow от чрезмерного числа пикселей и не более 100 кадров.

Одновременная запись одного документа блокируется `.ingest.lock`. После аварийного
завершения lock и `.staging-*` могут остаться: удалять их вручную можно только
убедившись, что процесс загрузки уже не работает. Сохранённые версии не редактируйте.
Перемещение каталога защищает от публикации частичного результата при обычной ошибке;
гарантия сохранности при отключении питания пока не реализована.

`data/processed/` уже исключена из Git: внутренние PDF и runtime-manifest не попадают
в коммиты. Не направляйте хранилище в отслеживаемую папку без настройки `.gitignore`.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверяются сохранение и хеш, число страниц, повторная загрузка, новая редакция,
повреждённый/зашифрованный/пустой PDF, небезопасный ID, отсутствующий файл,
повреждение сохранённого оригинала и блокировка параллельной записи.
Также проверяются DOCX с таблицей и изображением, XLSX, PPTX, изображения,
код без выполнения, кодировки UTF-8/16/32 и CP1251, структурированный текст,
неизвестные расширения, бинарные файлы и совместимость старого PDF manifest.
Тесты используют синтетические документы и не требуют внутренних файлов.

## Чекпоинт 2: рендеринг

Работает как локальная команда, в том числе на сервере без рабочего стола.
API/сетевого сервиса нет. Для PDF используется PDFium (`pypdfium2`),
для DOCX/XLSX/PPTX — LibreOffice в headless-режиме, затем тот же PDFium.
LibreOffice устанавливается отдельно от Python:

```powershell
winget install --id TheDocumentFoundation.LibreOffice --exact --source winget
.\.venv\Scripts\python.exe -m pip install -e .
```

На Linux нужен системный пакет LibreOffice и шрифты документов. Путь находится через
PATH; также поддерживаются `SOFFICE_PATH` и `--soffice`. Каждый запуск конвертации
использует отдельный временный профиль LibreOffice; окно не открывается.
Временные профиль, входной файл и промежуточный PDF располагаются в системном
временном каталоге, а не в глубокой папке версии: это устраняет сбой LibreOffice
на длинных путях Windows. Окончательный PDF копируется в папку рендера.

Отрендерить все сохранённые версии:

```powershell
.\.venv\Scripts\python.exe -m rag_pipeline.render --all --dpi 150
```

Команда создаст `data/processed/documents/render-index.html` и `render-report.json`.
Откройте индекс браузером: из него доступны галереи страниц и просмотр текста.
Если хотя бы одна версия не обработана, код завершения 1 и статус `partial_failure`;
результаты остальных версий сохраняются. Пакетный запуск однопоточный.

Для одной версии укажите её каталог из результата загрузки:

```powershell
.\.venv\Scripts\python.exe -m rag_pipeline.render "data\processed\documents\travel\sha256-<полный хеш>" --dpi 150
```

Структура внутри каталога версии:

```text
original.*
manifest.json                       # остаётся неизменным
renders/
  render-<отпечаток настроек>/
    render_manifest.json
    index.html                      # галерея или текст по строкам
    document.pdf                    # только для Office
    pages/page_0001.png              # PDF/Office, все страницы, начиная с 1
    frames/frame_0001.png            # изображения, все кадры, начиная с 1
```

Для Office число страниц появляется в manifest рендера и относится именно к
`document.pdf`. Исходный manifest DOCX/XLSX/PPTX сохраняет `page_count: null`.
Для изображений сохраняются размеры/кадры, применяется EXIF-поворот, прозрачность
отображается на белом фоне; исходные байты остаются прежними.
Для текста, Markdown, HTML и кода формируется экранированный HTML с номерами строк
и якорями `#L1`, `#L2`, …; Markdown показывается как исходник, код и HTML не выполняются.
Искусственная пагинация текста не создаётся.

`render_manifest.json` содержит источник и SHA-256, ID версии и рендера, параметры,
версии PDFium/Pillow/LibreOffice, размеры изображений, контрольные суммы всех
артефактов, путь к просмотру, предупреждения и `visual_review: pending`.
Статус `ready` означает технически завершённый рендер, а не подтверждённую полноту
будущего извлечения. Нужна визуальная проверка, особенно схем и таблиц.

Повторный запуск с теми же настройками проверяет целостность артефактов и возвращает
`cached: true`. Другая DPI/версия движка создаёт отдельный результат. После изменения
шрифтов используйте, например, `--revision fonts-v2`: перечень шрифтов не входит в
автоматический ключ. Повреждённый кэш вызывает ошибку, не перезаписывается скрытно.
Исходник проверяется по SHA-256 до и после рендеринга.

Готовая папка публикуется после обработки всего документа; временная папка очищается
при обычной ошибке. `.render.lock` блокирует параллельные записи одной версии;
после аварии проверяйте отсутствие живого процесса перед ручным удалением lock.
PDFium нельзя вызывать одновременно из нескольких потоков одного процесса:
для параллельного сервера позже нужны отдельные worker-процессы.

Ограничения: 72–300 DPI (по умолчанию 150), до 40 миллионов пикселей на страницу/кадр,
до 5000 PDF-страниц, до 100 кадров и до 200000 текстовых строк. Конвертация Office
имеет таймаут 120 секунд. При неподходящем лимите команда завершится явной ошибкой.
Страницы PDF, включая пустые и повёрнутые, сохраняются; число страниц сверяется
с исходным manifest.

LibreOffice может менять переносы/шрифты и сложные объекты относительно Microsoft
Office. XLSX рендерится по настройкам печати, поэтому не заменяет извлечение всех
ячеек; PPTX — статические слайды без анимаций и заметок. Последующие этапы должны
работать также с оригиналом, а не только с производным PDF.

Проверки: обычная команда `unittest` выше включает рендеринг цветного PDF, поворот,
пустую страницу, кэш, повреждение артефактов, текст/кодировки, многостраничный TIFF,
атомарность и реальную конвертацию DOCX/XLSX/PPTX. Последняя явно пропускается,
если LibreOffice отсутствует.

OCR, Docling/OpenParse, чанки, векторный поиск и генерация ответов пока не подключены.
