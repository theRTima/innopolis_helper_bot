# Аналитика обращений

Панель «Искры» помогает найти повторяющиеся затруднения. Например, вопросы
«Где календарь рабочих дней?» и «Как открыть производственный календарь?»
могут попасть в одну группу. По ней видны число вопросов и пользователей,
результаты ответов и предложение проверить навигацию или справку.

## Запуск с ботом

1. Установите зависимости проекта и запустите бота обычным способом. Он
   применит миграцию `0002_question_analytics` к существующей базе. Она добавляет
   таблицу разметки и индекс по дате вопросов.
2. В `.env` задайте длинный пароль из ASCII-символов в `ANALYTICS_PASSWORD`.
   Имя пользователя по умолчанию — `admin`. Его можно сменить через
   `ANALYTICS_USERNAME`.
3. Запустите разметку в отдельном терминале. Она читает новые вопросы из той
   же базы и использует настроенный `LLM_*` провайдер. Код ответа в Telegram
   не ждёт этот процесс.

   ```bash
   python -m app.analytics --watch
   ```

   `python -m app.analytics` обрабатывает до 60 вопросов за один проход.
   `--watch` повторяет проход каждые 30 секунд после завершения предыдущего.
   Ограничение можно поменять через `--limit`. Для MVP запускайте один процесс
   разметки на базу. Если запрос к модели не удался, вопросы остаются в очереди.
4. Запустите панель в ещё одном терминале и откройте
   [получившийся адрес](http://127.0.0.1:8001). Для доступа с других машин
   используйте HTTPS и ограничьте доступ к панели.

   ```bash
   python -m uvicorn app.analytics.web:app --host 127.0.0.1 --port 8001
   ```

## Демонстрация

В PowerShell из корня репозитория, в окружении проекта:

```powershell
$env:ANALYTICS_DEMO = "1"
python -m uvicorn app.analytics.web:app --host 127.0.0.1 --port 8001
```

Этот режим показывает вымышленные обращения с подготовленной разметкой.
Он работает без токена Telegram, базы и запросов к модели. Живую классификацию
можно показать отдельным прогоном обработчика на вопросах, сохранённых ботом.
Для возврата к рабочей базе уберите `ANALYTICS_DEMO` из окружения.

## Что означают показатели

- Единица подсчёта — сохранённый вопрос, то есть одно сообщение с вопросом.
  Число пользователей считается отдельно по уникальным ID.
- Ответ с источником содержит хотя бы одну ссылку на фрагмент, который получил
  бот. Показатель описывает наличие источника, а оценка «помогло» — реакцию
  пользователя. Для старых строк исход может быть неизвестен.
- «Без подтверждения» объединяет вопросы, для которых поиск ничего не нашёл, и
  ответы модели без ссылки на найденный фрагмент. Технические ошибки видны отдельно.
- Долю «помогло» панель показывает среди полученных оценок. Она не измеряет
  долю автоматически решённых обращений.
- Карточка появляется от трёх похожих вопросов и двух пользователей. Сигнал
  роста показывается, если в каждом из двух периодов есть хотя бы пять
  вопросов, все размечены, число вопросов группы выросло минимум на два и
  доля выросла хотя бы на пять процентных пунктов. Это рабочие пороги для
  отбора тем для проверки, а вывод о причинах остаётся за сотрудником.
- Периоды имеют одинаковую длительность и отсчитываются от текущего момента.
  Панель показывает даты в UTC. Для прогноза нагрузки нужна реальная история.

## Настройка для другого продукта

`ANALYTICS_AREAS_FILE` задаёт путь к UTF-8 JSON со словарём областей
продукта, например `{"checkout": "Оформление заказа", "returns": "Возвраты"}`.
Коды областей должны быть стабильными. Типы вопросов общие для продуктов.
Вопросы получают одну область, один тип и, когда возможно, конкретную тему.
Модель предлагает тему или выбирает одну из недавно найденных групп. Если
изменить коды областей, уже сохранённая разметка останется под прежними кодами.

При `ANALYTICS_SHOW_EXAMPLES=1` авторизованный пользователь панели увидит
до двух примеров на карточку. Примеры по умолчанию скрыты. Распознаваемые
контакты и ссылки скрываются в примерах и тексте для модели. Это ограниченная
фильтрация, поэтому используйте согласованный с вашей командой режим работы
с обращениями.

## Подключение эскалации

Когда обработчик передачи оператору появится в боте, используйте уже
сохранённый `question_id`:

```python
await db.record_escalation(question_id=question_id, status="requested")
# После успешной доставки в чат поддержки:
await db.record_escalation(question_id=question_id, status="delivered")
# При ошибке отправки вместо delivered используйте failed.
```

Панель считает обращения, для которых записан такой статус, и отдельно
показывает подтверждённые доставки и ошибки. Успешную доставку поздний
повтор события не перезаписывает.
